## Findings

Each finding meets the threshold in `integrate-review.md`: it names a failing
condition against the intended result. Integration `incremental-delivery-k4`
must check each against the source before acting.

1. **The scope decision has no named owner.**
   `plugins/grove/skills/grove/references/decompose.md:24` and
   `plugins/grove/skills/grove-planning/SKILL.md:37` both say a narrower
   delivery needs "an explicit scope decision". Neither says who decides.
   An AFK planning or decompose session can therefore declare its own
   narrowing and drop broader preexisting acceptance. That is the exact
   premature-drop risk the charter names. `retire.md` already states the
   precedent: "An agent never prunes on its own". A prune needs explicit human
   confirmation. The new text should name the same owner. Alternatively, it
   should require the human to record the decision in an ancestor brief. Until
   then, an AFK session must keep the live remainder.

2. **The stalled-handoff response can create a new endless relaunch.**
   The "Repeated handoffs with unchanged acceptance" paragraph in
   `decompose.md` says to leave the task live when a prerequisite blocks the
   attempt. It says the same when the session must stop early. `driver.md` says
   the loop reselects a live leaf. A session ends with the continue command
   after "record the blocker, leave live". The driver then relaunches it into
   the same blocked leaf with no change. The paragraph names no exit. It should
   send a blocker with no finite unblock to the human-input handoff in
   `execute.md`. That handoff states the pending decision and finishes the
   turn. Force-stop is the other exit. The same paragraph tells any task to "do
   necessary bounded repairs inline", and that includes a `review-*` task. This
   contradicts `review.md`, where a review edits nothing. The repair clause
   should apply to producers and integrations only.

3. **Stale unconditional "externalise" wording survives.**
   `plugins/grove/skills/grove-finish/SKILL.md:58` and `CONTEXT.md:418` still
   say every session is told "to externalize surfaced work rather than
   absorb it". The producer removed that unqualified rule from the spine and
   replaced it with the acceptance-connection test. A finish session reads the
   old sentence, so it can still cut a leaf for any surfaced work and relaunch.
   The finish skill's table row for "externalised work instead" has the same
   gap. Qualify both to apply the admission test in `decompose.md`.
   `CONTEXT.md:724` ("externalise it to the tree") concerns doubt reviews and
   is not a finding.
