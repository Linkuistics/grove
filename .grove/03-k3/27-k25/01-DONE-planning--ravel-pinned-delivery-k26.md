# ravel-pinned-delivery-k26

## Goal

Grow working Git-source implementation and acceptance leaves from the
delivered local route, without repeating or redesigning its public API.

## Context

Inspect the current implementation, tests and Taskfile of Ravel. Inspect its
package and install inputs and its accepted specification. Follow the
instructions of that repository.
Consume the owning commits and measured limits of the local node. The Settled
inputs of the parent give the identity and the Ravel task names.

No implementation belongs here. Use the reviewed Rhai contract repair and the
exact-base, named-bookmark and rebase handoff of the parent before you cut
implementation.

## Done when

- Cut complete public Git acquisition and reuse increments with fixtures,
  documentation and reusable tasks. Keep multi-source failure atomic at the
  descriptor and launch boundary, and preserve the local path.
- Schedule exact full commit and object-format pins, the rejection of tag
  objects and refs, and moved refs. Schedule an unavailable commit or subdir,
  gitlinks, literal LFS pointer bytes, path collisions and symlink checks, with
  local Git fixtures.
- Schedule a warmed launch with remote access and Git absent, and a transport
  spy that proves zero calls. Schedule a cold unavailable pin beside a cached
  neighbour. Include corruption, cancellation and reap, deadlines, bounded
  redacted diagnostics and simultaneous publishers. Include old readers through
  pin, configuration and source changes.
- Include source-origin protection on cached reuse, actual confined resource
  reads and mixed local and Git settings. Include installed dependency
  documentation and checks, and the applicable full and book checks of Ravel.
  Cover the complete public acceptance table.
- End with exact owning commits and reproducible independent installed-pair
  inputs for the dual-major work of Grove. Add actual implementation and
  acceptance leaves before retiring. A plan is not the delivered behaviour of
  this node.
- Assign removal of the temporary unsupported-Git refusal of the local build
  and its fixture to the public Git increment. Preserve the failure order before
  configuration for actual acquisition errors, under the settled contract.

## Notes

No shared settings or install change, and no release. If you find an upstream
defect, cut precise repair work before its consumer rather than weaken
acceptance.

## Decisions (running log)

**Base observed at planning.** On 2026-11-02, `jj git fetch` in
`Ravel.skill-directory-delivery` reported no change. Local `main` and
`main@origin` are both `24a545236185`. The bookmark `skill-directory-delivery`
is at the local output commit `1d50dae5d29e`, with an empty working-copy change
above it. The line needs no rebase today. The first implementation leaf still
fetches and records its own base at entry.

**Seams observed.** The temporary refusal is `refuse_git` in
`skills::watched`, with the unstable code `skill_git_unsupported`. Both public
readers reach it: `skills resolve` through `resolve`, and `start-session`
through `launch::prepare` and `resolve_protecting`. One change at that point
therefore enables Git at both seams together. `skills::origin` assumes a local
source and marks Git unreachable.

The settings parser already checks the Git
record: the full lowercase pin, the locator forms, embedded credentials and
relative paths. The cache holds three directories: staging, snapshots and
descriptors. The descriptor publishes only after every source passes, so
multi-source atomicity is structural. Internal fault seams exist under
`#[cfg(test)]` in `skills::faults`. No Rust Git dependency exists, and the
formula template declares no dependency. The Linux test image installs Git.

**The first increment is online exact acquisition at both public seams.** It
removes the temporary refusal and its fixture. It acquires the exact commit
and `subdir` through Git on `PATH`, extracts the tracked objects and passes them
through the existing manifest, check and publication path.

Transport hygiene stays in this increment. Every Git call, the first one included, must be
noninteractive and must run no hook, filter or submodule. It must also receive
no completion authority. A build without those properties is not a safe
working state.

**Offline reuse is the second increment.** Online pinned delivery is useful
alone, because each resolution acquires the exact commit. The acquisition key
record and the checked cache hit with no network and no Git then land
together. Corruption, pin changes and the race of two publishers of one key
land with them. The key
record has no other reader.

**Hardening follows in the order of the local stage.** Transport bounds,
deadline, cancellation and diagnostics come third. Confinement and lifetime
acceptance of Git and mixed sources come fourth. The installed Git dependency
and the formula decision come fifth. They follow the cache hit, because the
installed checks prove a hit without Git. The handoff closes the stage, like
`ravel-local-handoff-k61`.

**No planning review.** Each leaf cites the reviewed contract `822c0ed2` and
its acceptance rows directly, as the local plan did. Producers cut any earned
`review-impl` lazily and insert it before the handoff leaf.

**Rows outside this stage.** Actual harness trials, delegate authority and
directory recovery after compaction belong to `common-loading-acceptance-k29`.
Publication belongs to `discovery-rollout-k6`.
