# walkthrough-method-k3

## Goal

Independently research evidence-backed methods for explaining a substantial
codebase in a conceptually ordered, self-contained Markdown book for an expert
technical reader.

## Context

- The downstream consumers are `book-system-k6` and
  `walkthrough-skill-delivery-k19`.
- Search outside this repository only for communication and learning-design
  evidence. Repository source, tests, models, and authoritative dependency
  documentation remain the evidence for technical claims.
- Structure the report around the downstream questions below, not around the
  order in which sources are found.

## Done when

- The report compares established approaches to concept ordering, literate code
  exposition, worked examples, progressive disclosure, and expert-facing
  technical prose.
- It gives actionable criteria for deciding when required context should be
  repeated locally and when a cross-reference is sufficient, including the
  split-attention and redundancy risks.
- It addresses how a reader can follow code in explanatory order while a
  fragment graph still proves exact, complete source reconstruction.
- It identifies failure modes in long multi-page walkthroughs and concrete
  mitigations for navigation, cognitive load, and self-containedness.
- Every material external claim has a primary or authoritative citation, and
  the report clearly separates evidence from the researcher's inference.
- The report ends with explicit answers for the book-system design and for the
  generic skill's elicitation, authoring, and verification procedure.

## Notes

Prefer durable research, standards, primary studies, and maintained first-party
guidance over generic writing advice. Look specifically for what failed in
real, sustained use, not only for introductory recommendations.
