# staging-claude-native-trial-k285

## Goal

Prove in the staging HOME that the Claude Code native residue works beside
Ravel delivery: the always-on hooks, `/guardrail` and the user-invoked
skills.

## Context

- The parent brief holds the trial list, the staging layout that
  owner-staging-hooks-k251 left and the cost of a pack repair.
- "Native residue" of `docs/specs/owner-skill-delivery.md` states the route
  of each capability.
- `staging_trial.py` refuses an unknown case field. A new verdict adds its
  field and its tests in `test_staging_trial.py` together.

## Done when

- A Claude Code session runs the technical-communication hooks, and its
  native listing holds no `technical-communication` skill. If Claude Code
  lists the root `SKILL.md` as a skill, the trial fails, and the layout
  needs repair.
- On Claude Code, `/guardrail` runs from `guardrail@personal`, and no Ravel
  root holds `guardrail`.
- The inventory after owner-inventory-exceptions-k264 accepts the enabled
  `guardrail@personal` exception and nothing wider. Its staging rows show no
  other unclassified entry.
- A user-invoked skill, `authoring-conventions`, is not loaded unless the
  task names it.
- The evidence document records each trial, its versions and its result. It
  reconciles the item of "Not measured" about a root-level `SKILL.md`.

## Decisions (running log)

- owner-staging-capabilities-k250 became a node with three children,
  because its trials need new verdicts, real runs on both harnesses and an
  evidence section each. This leaf takes the Claude Code native residue.
- Ravel wraps the first prompt in its discovery text, so `/guardrail`
  cannot be the first prompt. The owner types it in a later turn. The case
  sends it as a later turn through the compaction case's feeder, with a new
  case field `turns`.
- The document gate of the hooks skips files under the temporary roots, and
  each staging work tree is under `/private/tmp`. The case writes its gate
  file into `OUT/gate` through the placeholder `{gate}`. The gate file comes
  before `/guardrail`, because the guardrail freeze stops a write outside
  the work tree.
- An exploratory session on 2026-11-10 showed the signals. The init event
  names each plugin's directory. The session file holds a
  `hook_additional_context` for SessionStart, UserPromptSubmit and
  PostToolUse. The hooks write a reply log in the staging HOME. The stream
  holds only the SessionStart hook events.
- `authoring-conventions` gets two cases: `user-invoked`, whose task does
  not name it, with a new verdict `forbids`, and `user-invoked-named`, which
  names it and is the positive control through `requires`.
- The third inventory control first planted a skill in `~/.agents/skills`.
  The inventory classifies each unknown entry of a Codex root as a stale
  copy that the switch deactivates, which is no anomaly. The control now
  plants it in `~/.claude/skills`, which gives `UNCLASSIFIED`.
- The Codex positive control `user-invoked-named` read
  `authoring-conventions` at event 6. It wrote the file through a shell
  heredoc, which the shared classifier does not count as an edit, so its
  `requires` verdict failed. The run stays the run of record. The `forbids`
  verdict, applied to both named runs, reports the load, which is the
  control's purpose.
- Claude Code loads `guardrail@personal` from the keg's directory, but the
  inventory reads the cache copy. The gap went to
  `inventory-guardrail-loaded-dir-k288`, because it changes the inventory
  and its controls, not this trial.
