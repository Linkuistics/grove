# 11.1-[24]-id-grammar

**Kind:** work

## Goal

Build the v2 **id model**: the parsed-name type + pure functions every dir-based
verb consumes, replacing `leaf_id`'s flat-position model (ADR-0035 §1–4).

## Done when

- Parse/render round-trips a **leaf** `NN-[DONE-]<slug>-[<key>].md` and a **node
  dir** `NN-<slug>-[<key>]/` (and the plain root `BRIEF.md`): 2-digit zero-padded
  per-level position, optional `DONE` infix after the position, `[key]` as the
  last token before `.md`/`/`.
- A **per-level numeric comparator** orders siblings (`01 < 02 < … < 99`); the
  full order is the directory walk (11.2's `pick`), so the comparator is per-level
  only, not a global vector.
- Slug/`[key]` validation; lenient parse (a foreign name is "not a leaf", never a
  panic — keeps the loop unjammable, as in v1).
- Unit-tested in isolation (no verb-path coupling), mirroring `leaf_id`'s test
  density.

## Notes

- Decide the **`[key]` delimiter**: keep `[n]` (shell-glob wart on the CLI) or
  switch to a glob-safe form (e.g. `-k12`). Raise with the operator — see node
  BRIEF / ADR-0035 open question.
- Keep the **permanent-key** semantics from ADR-0033 exactly: `next = max[n]+1`,
  never reused, `.DONE`/done leaves still counted.
