# 11.7-[29]-install-and-reflip-v2

**Kind:** work — **USER-GATED** (confirm before the live flip)

## Goal

The live v2 flip — delivered through the **real release pipeline**, not a local
build+install: merge this grove to `main`, push, cut a **major** release, update
the Homebrew tap, and `brew upgrade grove`. The released v2 binary then
adoption-migrates the live trees v1-flat → v2-dirs on their next `grove do`, and
ships the matching binary-embedded global skill. Mirror of 070/040's adoption
mechanics, one scheme version later — but released, not hand-installed.

## Done when

- This grove is merged to `main` and pushed (the v2 source + embedded `content/`
  prose land on `main`).
- A **major** release is cut (`scripts/release-{doctor,build,publish}.sh`); the
  version bump is the visible v1→v2 scheme break.
- The Homebrew tap (`Linkuistics/homebrew-taps`) formula is bumped to the new
  version and `brew upgrade grove` installs the v2 binary as the live `grove` /
  `grove-llm`.
- A reviewed `grove do` adoption-migrates a live tree v1-flat → v2-dirs in one
  reviewable commit (per `migrate-v1-to-v2-[27]`), order / done-ness /
  brief-chain / keys preserved; the global skill at `~/.claude/skills/grove/`
  matches the v2 binary (content-hash stamp), idempotent re-run does nothing.
- `grove-general-improvements` re-flips by the same adoption on its next `grove do`.

## Notes

- **USER-GATED**: confirm before the release + first real adoption-migrate.
- **Release, not local install** (operator directive, 2026-06-22): the v2 flip is
  a real major release through Homebrew, *not* a local build+install. A release
  cut from `main` reinstalls the released binary over any local dev binary, so a
  `cp`-onto-PATH dev reflip is fragile and must not be the delivery mechanism.
- **Sequencing with the finish cycle**: "merge this grove to `main`" overlaps the
  grove's own Finish step (which also merges to `main`). Settle at execution time
  whether this leaf *is* effectively the finish (merge → release → `brew upgrade`
  → the released binary migrates the live trees), or whether the grove finishes
  first and the release follows. `rationalise-adrs-and-docs-[34]` runs before this,
  so the corpus is clean at release.
- Same choreography as 070/040 for the adoption-migration mechanics (the worked
  precedent — read its retired leaf), but delivered via release.
