# 6.3-[13]-migrate-on-adoption

**Kind:** work

## Goal

Make **`grove do` migrate an old-format tree on adoption**: when it opens a grove
whose `.grove/` is old-format, run `grove migrate` (020) — committed as a reviewable
change — **before** driving, so the rest of the loop sees only new format. This is
the mechanism that performs the flip for this grove and for any other in-flight old
grove on its next `grove do` (ADR-0034).

## Context

Read **ADR-0034** (the flip; adoption migrates) and **ADR-0032** (the self-driving
loop; `restart ≡ continuation`). Entry points: `src/loop_driver.rs` +
`src/launch.rs` (`grove do <name>` — worktree create/resume, then the loop).
Format detection: an old tree has node *directories* / a `done/` dir / `NNN-slug`
files with no `[key]`; a new tree has flat `<position>-[<key>]-…` files
(`leaf_id::parse` returns a keyed id). Depends on **020** (the migration) and
**010** (new-format verbs live).

## Done when

- On `grove do`, before the first task launch, `.grove/` is format-detected; if
  old, `grove migrate` runs and its result is **committed** (a clear, reviewable
  commit — e.g. `grove(<name>): migrate task tree to dotted-decimal scheme`), then
  driving proceeds new-format.
- **Idempotent**: a new-format (or already-migrated) tree is a no-op — no commit,
  no churn. Detection is total and lenient (foreign files never trigger a spurious
  migrate).
- Safe under `restart ≡ continuation`: a re-run after a partial/aborted migrate
  re-derives cleanly (migrate is itself re-runnable; the commit makes the boundary
  crisp).
- Tested: an old fixture tree adopted → migrated + committed + drivable; a
  new fixture tree adopted → untouched.

## Notes

- Detection rule: "any top-level `.grove/` entry parses as a new-format keyed file
  ⇒ new; else old (and non-empty)". Keep it in `grove-llm` / a shared helper so the
  loop driver and `grove migrate` agree.
- This is the only place adoption auto-commits to the grove branch; everything else
  the loop does is the agent's own commits. Keep the migrate commit isolated and
  self-describing so it reviews cleanly in history.
- Confirm with the user before the **first** real adoption-migrate of this grove
  (it happens at the 070 install/handoff, not here) — building + fixture-testing
  the mechanism here is inert for the live tree.
