# 9.1-[30]-migrate-seeds

**Kind:** work

## Goal

Re-home the captured content of the 4 `grove-meta` seeds **before** 9.2 deletes the
inbox subsystem and the `grove-meta` branch (after which dropped content is gone
from reach). This is the **last use** of the inbox machinery. User decision:
*delete the subsystem, but migrate the seeds first.*

## Context

Seeds present on the `grove-meta` branch (`<repo>/.grove-meta/inboxes/<name>/`):

- **`grove-general-improvements`** — a **live worktree**; the catchall the user
  captures grove CLI/methodology/skill issues into ([[feedback_capture_grove_infra_issues]]).
  Its observations matter most.
- **`grove-do-subsumes-start-continue-and-prompts-finish-cycle`** — a grove idea;
  check whether the 040 loop work already subsumed it.
- **`grove-status-should-show-active-grove-grove-versions`** — **mooted** by this
  node's shed (`grove status` deleted; one binary / one global skill → no per-grove
  version to show). Likely reject.
- **`rmux-web`** — likely **mooted** by 080 (the whole rmux/TUI substrate was
  deleted). Verify, then reject if dead.

Read each seed first: `grove inbox show <name>` (diagnostic) or read the files
directly under `.grove-meta/inboxes/<name>/`.

## Done when

- The `grove-general-improvements` observations are re-homed into its **live
  worktree** so its next session sees them — a durable note it reads at bootstrap
  (e.g. a markdown file in that worktree, or appended to its root brief / a new
  leaf in its tree). Do **not** drive that grove's session from here; just leave the
  content where its next `grove do` will surface it. (That grove is still
  old-format; keep the re-home format-agnostic — a plain note, not a new-format
  leaf injected into an old-format tree.)
- The other 3 seeds are triaged: any still-valuable content re-homed to a durable
  location (this branch's `docs/` or the relevant worktree); the rest explicitly
  rejected (dropped — accepted to vanish with `grove-meta` in 9.2).
- The seeds are emptied/removed on `grove-meta` (`grove-llm inbox-drain` finalize,
  or `grove-llm inbox-remove --for=<name>`), so 9.2's `grove-meta` teardown is clean
  and refuses nothing for pending observations.
