# 9.3-[32]-shed-install-and-status

**Kind:** work

## Goal

Delete the **install / materialise / `VERSION.md`** machinery and **`grove status`**
(ADR-0001/0007/0008), replaced by 070's binary-provisions-global-skill. Includes the
**latent `load_prompt` repoint** the node brief flags.

## Done when

- **Code deleted:** `src/install.rs`, `src/fetch.rs`, `src/extract.rs`,
  `src/uninstall.rs`, `src/version_md.rs`, `src/status.rs`, and their tests
  (`tests/install.rs`, `tests/extract.rs`, `tests/uninstall.rs`,
  `tests/version_md.rs`, plus the `status` unit tests are in-module). Drop their
  `pub mod` lines in `lib.rs`.
- **`cli.rs`:** drop `Command::Install`/`Uninstall`/`Status` + dispatch arms +
  `InstallArgs`/`UninstallArgs`/`RepoArgs` (confirm `RepoArgs` has no surviving
  user). Update the top-level `about`/command doc-comments if they advertise these.
- **`load_prompt` repoint (the real fix):** `launch::load_prompt` and
  `loop_driver` must read prompts from the **global** skill dir, not the repo-local
  install path. Point at `provision::global_skill_dir().join("prompts")`. Verify
  the loop then launches off the *current* prompts (the 276-byte `continue.md`, not
  the stale 80-byte main-repo mirror). Add/adjust a test
  (`tests/launch.rs`/`tests/loop_driver.rs`) so this can't silently regress.
- **`harness.rs`:** keep the struct + `HARNESSES` + `by_name`/`detect_in_repo`/
  `select` + `project_dir`/`project_dir_path` (used by launch/loop_driver/
  harness_stamp). Remove `install_path` **iff** nothing live still calls it after the
  repoint (status + install were its callers). `harness_stamp.rs` is untouched.
- **Glossary (`content/CONTEXT.md` + worktree `CONTEXT.md`):** remove **Install
  scope**, **Path-scoped commit**, **Lifecycle walkthrough**, and the
  **cli/repo/worktree version** entry; trim **Global skill provisioning** so it no
  longer references the dead [[cli version]]/[[repo version]]/[[worktree version]]
  drift model (the "whose code 090 deletes" clause is now satisfied — state it as
  done, not future).
- **ADRs marked Superseded** (`superseded by ADR-0031`, one-line why): 0001, 0007,
  0008.
- **Docs:** drop/redirect any `docs/workflows/` install lifecycle-walkthrough and
  `README.md` install/status references that now describe deleted verbs.
- `cargo build` + `cargo test` green; `grove --help` shows only `do`/`migrate`/
  `takeover`/`retire` (+ whatever else survives), no `install`/`uninstall`/`status`.

## Notes

- `grove --version` (clap's built-in) still answers the version question — keep it.
- Coordinate the `inboxes`/`meta` references in `install.rs` with 9.2 (see 9.2
  Notes): whichever runs second deletes the dangling call. If 9.3 runs after 9.2,
  `install.rs` may already have a stubbed `meta init` call — just delete the file.
- `ureq`/`flate2`/`tar` deps were for fetch/extract — drop from `Cargo.toml` if no
  surviving module uses them (check `provision.rs` uses `include_dir`/`sha2`, not
  these).
