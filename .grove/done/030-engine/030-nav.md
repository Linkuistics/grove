# 030-nav

**Kind:** work

## Goal

Build the minimal **`Nav` surface** — a native ratatui widget (not an rmux pane, E3)
that lists groves and opens their harness. This is what makes `grove tui` usable for
more than one grove: the leader (`Alt-g`) focuses Nav, you pick a grove, its harness pane
opens/focuses.

Build:
- `tui::nav`: render a grove list from the presentation-agnostic core
  (`RepoView`/`MultiRepoView` — call it sync from async context, E1). Keep it **minimal**:
  a flat selectable list of groves with enough identity to disambiguate
  (`<repo>/<grove>` at N>1). No grouped/flat-ranked filtering, no inbox/lifecycle
  toggles — that richness is 050.
- Wire selection into the session/pane model (E3): selecting a grove opens its harness
  pane (`grove do <name>`, cwd = worktree) if absent, or focuses the existing `PaneId`
  from the `grove-name → PaneId` map. Focus returns to `Harness` on selection.
- Nav becomes the real target of the E4 focus machine's `Nav` state (replacing 020's
  stub): arrow/`j`/`k` to move, Enter to select, Esc back to the current harness.

## Context

Depends on 010 (loop/pane) + 020 (focus machine). The data already exists below the seam
(`RepoView::scan`, `MultiRepoView`); this leaf is pure presentation over it — no new core
logic. fs-watch ticks (010's `select!` arm) should refresh the nav list (groves
appearing/retiring). At 030 minimal scope the fleet can be the current repo's groves; the
full multi-repo fleet UX (grouped headers, ranked filtering, per-repo re-scan) is 050.

## Done when

- `Alt-g` opens Nav; it lists the groves; selecting one opens/focuses that grove's live
  harness pane; Esc returns to the harness.
- Opening an already-open grove focuses its existing pane (no duplicate pane).
- Nav rendering is covered by a headless unit test (list → `Buffer`);
  `cargo build`/`cargo test` green.

## Notes

This is the first multi-pane moment (more than one harness can exist across selections) —
it validates the `PaneId` map (E3). Park/close semantics for non-selected harnesses are
**050**; here a deselected harness pane may simply stay open/hidden — don't build
park-alive yet.
