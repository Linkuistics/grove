# Grove delivery after the Ravel extraction

Grove archives contain `bin/grove`, `bin/grove-llm`, `LICENSE`, `README.md`
and the complete readable `assets/ravel-policy` tree installed at
`libexec/ravel-policy`. The formula depends on `linkuistics/taps/ravel`. Ravel
provides its own public front, private worker, SDK, examples and runtime notices
from its own prefix and release version. No Ravel Rust library crosses the seam.
Grove keeps its local keyed-launch runner.

The former package and its build/typecheck/probe/install/compatibility tasks are
removed together. Compiler development dependencies belong to tools/ravel-policy;
strict checking uses independently installed Ravel declarations. `task check`
resolves Ravel from PATH (GROVE_TEST_RAVEL overrides it) and explicitly runs the installed caller assets.

## Installed archive checks

`task release:smoke` builds fresh Grove archives, admits the public Ravel 0.1.0
archives through the digest/target/exact-layout checks documented in
[ravel-target-inputs.md](ravel-target-inputs.md), and stages the dependency in a
separate prefix. For offline inputs, invoke `scripts/release-smoke.sh --archives
DIR --ravel-archives RAVEL_DIR TARGET...`. Missing or mismatched inputs fail.

Native, floor-container and QEMU routes use the same isolated caller cases.
They check both Grove commands, every caller asset, ordinary imports through
independent Ravel, lifecycle completion after reap and standalone output
publication, direct and symlinked fronts, and distinct project versions. Child
PATH contains selected system tools and Ravel, with no host Bun/Node or dispatch.
The lifecycle fixture supplies a filesystem workspace and a fake session's
teardown marker; it does not test jj commit operations or retire actual work.
Existing Rust jj/lifecycle suites own those behaviors.

QEMU header admission includes every ELF from both projects before registering
the CPU model. Existing glibc and above-CPU-floor controls remain shared with
Ravel's independent target runner. `task release:registration:test ARCHIVES=... RAVEL_ARCHIVES=...` checks real
combined ELF headers and missing/escape controls.
`task release:formula:test ARCHIVE=...` runs Homebrew itself in a private prefix;
its checksum fixtures are never publishable. The release formula test consumes installed
caller imports and executes Grove's standalone public boundary.

## Live installation boundary

The original installed 22.1.0 Grove/dispatch keg, personal policy and current
ending channel remain untouched. Cargo and direct helpers keep all old/new
authority scrubs. legacy-driver-transition-k50 owns the isolated upgrade/unlink
instrument; linux-standalone-floor-k52 supplies the missing real bubblewrap backend in the
existing CentOS floor userlands; grove-delivery-acceptance-k51 owns final rebuilt
all-target/formula acceptance. This contraction performs no release, installation or teardown.

Historical release notes, declared compatibility/authority fixtures, the original
live-driver contract and broader ownership prose assigned to k12 may retain old
names. Current workspace, archive, build/gate/formula and smoke consumers must
not depend on the removed source tree.

## Verified contraction boundary — k49

The frozen default `task check` passed all 14 principal checks, 1,378 workspace
nextest cases, nine doctests and six final/all books. Explicit installed command,
resolver and result tests passed all 19 executions; every retained prior gate
identity agrees individually. Only old-package cases were retired. Native Grove
archive consumers and the real private Homebrew install/test passed with Ravel
0.1.0 separately installed. Combined four-ELF registration and missing/escape
controls passed for both Linux targets. Ravel-only target smoke passed every
route with CPU/glibc controls. Missing/tampered independent inputs were refused
before the Grove consumer invoked any archive executable.

image lacks `/usr/bin/bwrap`. k52 prepares the real confinement environment before
k51's final rebuilt all-target acceptance. No Linux standalone pass is claimed
by k49. All 15,780 frozen subjects matched individually, and 2,076 protected
installation/config/adjacent-checkout subjects matched k48. Complete measurement,
case comparison, negative controls and coverage limitations are in `target/k49/`.
This evidence precedes its documentation/coordination promotion.
